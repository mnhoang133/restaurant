Cơ Chế Database & Thành Phần Cloud

Cơ sở dữ liệu đám mây (Cloud Database)

PostgreSQL lưu trữ trực tiếp trên nền tảng Supabase, giao tiếp thông qua Prisma ORM.

Cơ chế 2 chuỗi kết nối (Connection Pooling)

  • Cổng 6543 (DATABASE_URL): Đi qua PgBouncer (Pooler) gom kết nối khi web hoạt động, chống nghẽn RAM.
  • Cổng 5432 (DIRECT_URL): Kết nối trực tiếp vào Postgres, dùng riêng khi chạy lệnh prisma db push tạo bảng.
Singleton Pattern:

Khởi tạo duy nhất 1 phiên bản PrismaClient, tránh rò rỉ kết nối khi nodemon tự reload.

Cloud Storage (Lưu ảnh):

Tải ảnh lên Supabase Storage bucket, lưu URL vào DB; có cơ chế fallback cục bộ nếu gặp sự cố mạng.

Hạ tầng đám mây phân tán đảm bảo tính toàn vẹn và khả năng chịu tải.

Cấu Trúc Mã Nguồn & Cơ Chế SSR

Cấu trúc phân tầng (Layered)

  • prisma/: Schema 3 model & seed data.
  • src/middlewares/: id-parser, upload ảnh, error (404/500).
  • src/routes/: Tách Client (/dishes) và Admin (/admin/...).
  • src/controllers/: Nhận request, validate, điều phối PRG.
  • src/services/: Nơi duy nhất gọi Prisma truy vấn DB.
  • src/views/: 18 template EJS render giao diện.

Cơ chế SSR (Server-Side Rendering)

Server làm tất cả: Nhận request -> Controller lấy dữ liệu từ DB -> nạp vào template EJS -> nặn ra file HTML hoàn chỉnh gửi về.

Trình duyệt chỉ hiển thị HTML nhận được. Tuyệt đối không dùng fetch hay AJAX phía client để xin dữ liệu ngầm.

Mỗi thao tác chuyển trang hoặc gửi form, trình duyệt sẽ tải lại (reload) toàn bộ trang.

Luồng Xử Lý (Flow) & Kiến Trúc PRG

Luồng Đọc (GET)

  • Browser gửi request GET /dishes?q=...
  • Controller gọi Service -> Prisma truy vấn Postgres.
  • Render file EJS trả về HTML (mã HTTP 200).
  • Nếu ID sai định dạng hoặc không có trong DB: trả mã HTTP 404 kèm trang báo lỗi và link quay về.

Luồng Ghi (POST, PATCH, DELETE) - PRG

  • Validation: Dữ liệu nhập sai -> Server trả HTTP 400 và giữ nguyên dữ liệu trên form.
  • Chống trùng (Post/Redirect/Get): Lưu DB xong -> Server trả HTTP 303 Redirect sang trang chi tiết -> Browser tự mở bằng GET. Bấm F5 không bị gửi lại POST.
  • Xóa (DELETE): Bắt buộc qua trang xác nhận trước khi gửi ?_method=DELETE (thực hiện Xóa Mềm Soft Delete: isDeleted = true).

Mô hình chuẩn mực: dữ liệu an toàn, không gửi trùng lặp và phân định rõ ràng các phương thức HTTP.
